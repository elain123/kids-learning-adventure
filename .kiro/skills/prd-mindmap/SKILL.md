# PRD 思维导图生成（prd-mindmap）

> 输入：一个或多个 PRD 文档（Markdown）
> 输出：Markmap 思维导图大纲（.md）+ 可交互 HTML 思维导图（.html）

---

## 触发条件

当用户输入以下关键词或短语时，自动启动本流程，无需额外确认：

| 触发关键词 | 动作 |
|-----------|------|
| "生成思维导图" / "PRD思维导图" | 对指定 PRD 生成思维导图 |
| "把这个需求画成思维导图" | 对当前打开的 PRD 生成思维导图 |
| "需求脑图" / "PRD脑图" | 同上 |

---

## 路径参数定义

> ⚠️ 以下路径在流程启动时确定，后续统一引用，禁止中途写死路径。

| 参数名 | 说明 | 确定方式 / 推导公式 |
|--------|------|---------|
| `{PRD_FILE}` | 待处理的 PRD 文档 | ① 用户明确指定 → ② 当前打开的 PRD 文件 → ③ 最近使用的 `01-需求方案` 目录下的 PRD |
| `{REQ_DIR}` | 需求方案目录 | `{PRD_FILE}` 所在目录，通常为 `{增量目录}/01-需求方案` |
| `{INCREMENT_DIR}` | 增量目录 | `{REQ_DIR}` 的上一级目录 |
| `{OUTPUT_DIR}` | 思维导图输出目录 | `{INCREMENT_DIR}/06-思维导图`（不存在则创建） |
| `{MINDMAP_MD}` | 思维导图大纲文件 | `{OUTPUT_DIR}/{PRD文件名去后缀}_思维导图.md` |
| `{MINDMAP_HTML}` | 可交互思维导图文件 | `{OUTPUT_DIR}/{PRD文件名去后缀}_思维导图.html` |
| `{HTML_TEMPLATE}` | HTML 渲染模板 | `.kiro/skills/prd-mindmap/mindmap-template.html` |

> 若用户指定多个 PRD，逐个循环处理，各自生成一对 `.md`/`.html`；也可用"合并"关键词生成单个汇总思维导图（见第五步）。

---

## 路径推导优先级

1. 用户明确指定的 PRD 路径 > 当前打开的 PRD 文件 > 最近使用的 `01-需求方案` 目录下的 PRD
2. 若无法确定 `{PRD_FILE}`，**询问用户**："请指定要生成思维导图的 PRD 文档路径"
3. 若指定路径不是 PRD（不含"用户故事/功能点清单"等章节），提示用户确认

---

## PRD 章节结构参照

> ⚠️ 本技能**只提取三个分支**：验收要点、业务流程、功能模块。其余章节（需求背景/需求价值/非功能性需求/数据结构等）一律**不提取**。

标准 PRD 文档章节结构如下，解析时按此定向提取（章节标题可能有序号变体，按语义匹配）：

| PRD 章节 | 提取为思维导图节点 |
|---------|------------------|
| 文档标题（一级 `#`） | 思维导图根节点 |
| 用户故事表格 | 「用户故事」分支：仅提取**验收要点**（每条一个叶子节点），可保留故事名称+优先级作为分支标题 |
| 三、核心业务流程 | 「业务流程」分支：主流程节点、关键决策点 |
| 四、功能点清单 | 「功能模块」分支：按功能模块结构树逐层展开（核心分支，层级最深） |
| 五、功能详细描述 | 归并到「功能模块」对应子节点，补充关键规则 |
| 六、交互/边界 | 「功能模块」对应节点补充边界/异常 |

> ⚠️ 「功能点清单」（第四章功能模块结构）是思维导图的主干，必须完整还原其树形层级。
> ⚠️ 不提取：需求背景、需求价值、非功能性需求、数据结构。

## 执行流程

### 第一步：定位并读取 PRD

1. 按路径推导优先级确定 `{PRD_FILE}`
2. `readFile({PRD_FILE})` 读取全文
3. 校验是否为 PRD（含「用户故事」或「功能点清单」等特征章节）；不是则提示用户确认

### 第二步：解析章节层级

按「PRD 章节结构参照」表逐章提取，构建思维导图节点树（**仅三个分支**）：

1. **根节点**：文档一级标题（去除"— 产品需求文档（PRD）"等后缀，保留产品/功能名称）
2. **验收要点分支**：从用户故事表格提取验收要点（每条验收要点为一个叶子节点）；分支标题可用「用户故事」并保留故事名称+优先级
3. **业务流程分支**：
   - 主流程：按流程图节点顺序提取为有序子节点
   - 关键决策点：每个决策点为一个子节点，其"条件→处理方式"作为叶子
4. **功能模块分支（主干）**：
   - 优先解析第四章「功能模块结构」代码块中的树形缩进（`├──` / `│` / `└──`），逐层还原为思维导图层级
   - 结合第五/六章补充每个功能点的关键规则（≤ 15 字摘要）

> ⚠️ 解析约束：
> - **只提取验收要点、业务流程、功能模块三个分支**，需求背景/需求价值/非功能性需求/数据结构一律跳过
> - 节点文本必须精简为短语，禁止整段复制 PRD 原文
> - 保留 PRD 原有的层级关系，不擅自增删层级
> - 树形代码块（`├──└──│`）必须按缩进准确还原父子关系

### 第三步：生成 Markmap 大纲（{MINDMAP_MD}）

将节点树输出为 Markmap 兼容的 Markdown 大纲，写入 `{MINDMAP_MD}`：

- 使用 `#` 标题层级 + 无序列表 `-` 表达层级
- 根节点用一级 `#`
- 一级分支（用户故事/验收要点、业务流程、功能模块）用二级 `##`
- 更深层级用无序列表缩进（每级缩进 2 空格）
- 优先级、状态等可用 Markmap 内联标记，如加粗 `**P0**`

**大纲结构示例：**

```markdown
# 品牌资产库

## 用户故事
- 品牌资产库核心库管理 **P0**
- 验收要点
  - 五大核心库卡片入口
  - 文件夹5层嵌套
  - 标签继承+冲突检测

## 业务流程
- 主流程
  - 进入品牌资产库
  - 查看五大核心库卡片
  - 切换库详情页
- 关键决策点
  - 移动文件→标签冲突弹窗
  - 删除文件夹→资产移动目标

## 功能模块
- 核心库卡片入口
  - 联想词库
  - 证据链库
  - SKU话术库
  - 内容模板库
  - 合规库
- 库详情页面
  - 文件夹树形结构（5层嵌套）
  - 资产列表（分页加载）
  - 版本历史时间线
- 资产详情
  - 在线预览
  - 标签展示
- 标签管理
  - 继承标签机制
  - 标签冲突检测
- 版本管理
  - vX.Y.Z 三段式版本号
  - 发起更新流程
```

> ⚠️ 写入约束：`{MINDMAP_MD}` 第一行必须是根节点一级标题 `#`，之后严格按缩进层级书写。

### 第四步：生成可交互 HTML（{MINDMAP_HTML}）

1. `readFile({HTML_TEMPLATE})` 读取模板
2. 将第三步生成的大纲内容替换模板中的 `{{MINDMAP_CONTENT}}` 占位符
3. 将标题占位符 `{{TITLE}}` 替换为根节点名称
4. 写入 `{MINDMAP_HTML}`

> HTML 使用 Markmap autoloader（CDN），打开即渲染为可缩放、可折叠的交互式思维导图。

### 第五步（可选）：多 PRD 合并模式

当用户要求"合并生成"或指定整个 `01-需求方案` 目录时：

1. 扫描 `{REQ_DIR}` 下所有 PRD（排除"目录""待删除"等非需求文件）
2. 以迭代/系统名称为根节点
3. 每个 PRD 作为一个二级 `##` 分支，其下按验收要点/业务流程/功能模块三个分支展开
4. 输出单一 `{OUTPUT_DIR}/{迭代名}_需求全景思维导图.md` 和 `.html`

### 第六步：输出确认

```
[✅] 思维导图已生成：
  - 大纲文件：{MINDMAP_MD}
  - 交互思维导图：{MINDMAP_HTML}
  - 根节点：{根节点名称}
  - 一级分支：用户故事（验收要点）/ 业务流程 / 功能模块
  - 功能模块节点数：{M}
提示：
  - 用浏览器打开 HTML 查看可交互思维导图（需联网加载 Markmap CDN）
  - .md 大纲文件完全离线可用
```

---

## 质量约束（强制执行）

1. **只保留三个分支**：仅输出验收要点、业务流程、功能模块，其余章节不提取
2. **层级保真**：功能模块分支必须完整还原 PRD 第四章树形结构，不丢层、不增层
3. **文本精简**：所有节点文本为短语（叶子节点 ≤ 20 字），禁止整段复制原文
4. **可渲染**：生成的 `.md` 必须是合法 Markmap 大纲；`.html` 打开后必须能正确渲染
5. **不臆造**：PRD 中没有的内容不得编造，缺失信息标注 `{待补充}`

## 输入/输出路径约定

### 输入
- `{PRD_FILE}`（单个或多个 PRD 文档）

### 输出
- `{MINDMAP_MD}` — Markmap 思维导图大纲
- `{MINDMAP_HTML}` — 可交互 HTML 思维导图
